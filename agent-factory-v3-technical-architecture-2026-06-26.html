智能体工厂 v3 — 技术架构深度分析

一个自主 ReAct 大脑把业务本体编译成事件图、逐个设计并亲手写出可运行的智能体、在隔离沙箱里真实部署到 Inngest 跑通事件链、并在验收门通过后才交付。本文逐层拆解它的工程内核：大脑的流式推理与接地、harness engineering（验证回路 / 约束解码 / 跨次学习 / 子大脑）、先编译后生成的确定性校验栈、真实部署桥、测试用例验证闭环，以及持久化与基础设施。

代码库 /Desktop/agenticOperator 模型 gemini-3-flash（OpenAI 兼容网关） 运行时 Inngest + Postgres + Neo4j(Allmeta) 前端 Next.js 16 · React 19

§执行摘要

工厂不是一条固定流水线，而是一个像 Claude Code / Codex 那样自己思考、自己决定下一步的大脑（conductor.ts）。它的可靠性来自三件事的分工：

  • 大脑提供智能 — 读什么、造什么、什么时候验证、失败了怎么反应，全由 LLM 在 ReAct 循环里自主决定。
  • 工具提供可靠执行 — ~20 个确定性工具（读本体 / 设计 / 写代码 / 校验 / 沙箱跑 / 诊断 / 反思…），每个都是纯粹、可测的能力。
  • 验收门提供真相 — 静态闭合 + AI 亲写代码过 TS 编译 + 真实沙箱跑通（带指纹防 stale）三道门全过才能 finish，杜绝"纸面成功"。

围绕这个核心是一整套 harness engineering：源级约束解码防幻觉、模糊接地把 LLM 写错的工具名绑到真名、refine/revert/score 带回归检测的迭代、隔离子大脑、按效果排序的持久技能库、跨次学习的反思、自动上下文压缩、人在环路 mailbox、进程内后台运行。下面逐层展开。

1Harness 大脑（ReAct 引擎）

大脑是一个流式 ReAct 循环：一个 LLM 推理 → 调一个工具 → 观察结果 → 再推理，直到它自己调 finish 且通过验收门。lib/agent-factory-v3/brain/conductor.ts · runBrain()

1.1 流式网关 streamTurn：重试、退避、402 降级

大脑通过 OpenAI 兼容网关流式调 LLM，并对上游不稳健做了硬化处理。lib/agent-factory-v3/brain/stream-gateway.ts

  • 流式拼装：异步生成器逐 token yield {t:"think"}；tool_calls 按 index 把 name/arguments 字符串逐块拼接，结束时 yield {t:"tool_calls"|"done"} + {t:"usage"} 计 token。
  • 重试 5 次 + 指数退避：检测 5xx / overload / timeout / rate-limit / econn 等瞬时特征 → 退避 2s→4s→8s→16s；4xx（自身 bug）不重试。
  • 402 余额降级：网关回"can only afford N"时，单次把 max_tokens 降到 0.9×N 立即重试（不占退避轮数）——这正是历史上"沙箱不部署"假象的真因被根治后保留的护栏。
  • 输出无上限：max_tokens 默认省略（用户拍板移除 token cap），逃生阀 FACTORY_BRAIN_MAX_TOKENS；温度 0.4。
// 瞬时错误 → 指数退避；402 → 单次降额重试（stream-gateway.ts）
const transient = (code >= 500 && code < 600) || /overload|50[234]|timeout|rate.?limit|econn/.test(msg);
if (!transient || attempt === MAX_ATTEMPTS-1) throw e;
await sleep(2000 * 2 ** attempt);   // 2s,4s,8s,16s

1.2 意图路由：不对每条消息都跑生成

System prompt 的第一条硬原则是先判意图：①信息性问题（有几个域 / 某域有哪些动作 / 某次运行发生了什么）→ 用 front-desk 工具查到答案后直接一段文字回答即结束；②闲聊/澄清 → 直接答；③明确要造/改/部署 → 才走 read_ontology→create_plan→design_agent→…→finish 完整流水线。这避免了"问个问题也重跑整条流水线"。conductor.ts · systemPrompt()

1.3 自动上下文压缩（无需 turn-cap 截断）

循环的"记忆"是每轮重发的完整消息历史。在硬域上它会无限增长。工厂不靠粗暴的 turn-cap，而是当历史超过 ~120k 字符时压缩：保留 system+goal + 最近 6 个工具轮，把更早的中段折叠成一段摘要。conductor.ts · maybeCompact()

层来源保证
Tier-1 结构化锚点buildStateSummary(ctx) 从 ctx 确定性生成忠实、免费、永远在；显式锚定"未解决问题"（校验未过的 agent、缺工具、未接地工具）
Tier-2 推理脉络summarizeDropped() 让 LLM 抽象摘要被丢轮次尽力而为（网关挂就退化到只用 Tier-1），捕捉"为什么这么决策"的细节

被折叠的细节仍可通过 read_spec / inspect_run 回取——只是被换出热上下文，不是真丢。工具结果本身也有 60k 字符上限（截断会显式标记，让大脑知道要重取而非脑补）。

设计决策无 token 预算上限（用户拍板）。MAX_TURNS=200 是唯一的 runaway backstop；真正的上下文管理靠自动压缩，而不是把循环截短。成本只做软阈值提示（FACTORY_COST_*_TOKENS，2M/4M），永不拦截。

3Harness Engineering 核心

这是工厂"造得对"的工程内核——一组围绕 LLM 不可靠性设计的机制，把一个会幻觉、会偷懒、会自称成功的模型，约束成一个能交付可运行系统的工程师。

3.1 验证回路 / 三道验收门（verifier-in-the-loop）

finish 不是说结束就结束——它原子地检查三层证据，任一不过就返回 ok:false，把大脑赶回去修。tools/index.ts · finish.execute()

关键：指纹防 stale-greenspecsFingerprint() 用 djb2 把每个 spec 的 slug|trigger|emit|tools|codeSource|代码哈希 折成一个等值串。任何 design/refine/revert/codegen 都会把 ctx.lastSandbox=null——所以"改完代码但拿改之前的绿沙箱来 finish"这条路被堵死：证据过期就必须重跑。

更微妙的是第三道门要求 fullChainRan（!partial && 到达成功终态 && 无 degraded），而不只是 agentsRan===deployed：因为沙箱的 coverage pass 会直接喂每个未跑 agent 的 trigger，一条断了的链也能凑到 agentsRan===deployed 却从未端到端连通。只有 fullChainRan 才是"链真的串通了"的信号。

3.2 三层防幻觉（接地）

LLM 最常见的失败是凭空造符号——写 parseResumeFile 而真名是 robohire.parseResume，或写本体里不存在的事件名。工厂用三层防护：

层机制文件
P5 源级约束解码：每轮把 design_agent/refine_agent 的 action / tools[] 参数 schema 注入 enum（真实动作名 / 真实工具名）。网关支持 JSON-schema enum 时，编码阶段就生不出不存在的符号。schema-grounding.ts
P1 桥接模糊接地：resolveToolName 四级（精确→规范化→子串→令牌超集），把 LLM 写错的名字绑到最接近的真名，并在结果里显式标"🔗 已对到真名"让大脑确认。tools/registry.ts
P2 后验拒绝：ungroundedEventTokens 扫 prompt/代码里本体没声明的事件名 token，作为警告 surface；validate_graph 的 ungrounded-event 硬判。tools/index.ts
// 令牌超集模糊接地：LLM 的 "parseResumeFile" → "robohire.parseResume"（registry.ts）
const queryTokens = new Set(toTokens(raw));            // {parse,resume,file}
for (const name of registry.names()) {
  const content = catalogContentTokens(name);       // 家族名后的有意义令牌 {parse,resume}
  if (content.every(t => queryTokens.has(t))) // 工具名的每个令牌都被查询覆盖 → 命中
    bestName = name;
}

3.3 迭代修订：预算、回归检测、回滚

  • refine_agent 保留每次的 prior 快照 + critique 到 ctx.attemptHistory，不是盲覆盖。
  • 预算：单 agent REFINE_BUDGET=3，全域 3×agent数，沙箱 MAX_SANDBOX_RUNS=8——防 churn 到超时。
  • 自动评分回归：每次 refine 后用四维（工具解析率/prompt 富度/决策覆盖/refine 健康）打分对比上一版，delta≤-10 或单维跌 ≤-20 判 regression，提示 revert_refine 回滚而非硬塞。

3.4 隔离子大脑（递归 ReAct）

spawn_subagent 递归调 runBrain，但 isSubAgent=true：独立 ctx、独立消息历史、只读工具集（READONLY_TOOLS + web_search，不能部署/改 agent），并转发父大脑的 abort signal（父被取消则级联取消）。用于"先深入调研某子问题再定阈值"而不污染主对话。tools/p2-p3.ts · spawn_subagent

3.5 持久技能库（按效果排序）

技能 = 织入 agent prompt 的指导 + 推荐工具 + 决策规则，落盘到 skills-library/<slug>/SKILL.md（YAML frontmatter + body）。read_ontology 暴露可复用技能，use_skill 调入。skills-library.ts

SkillsBench：按"证明有效"排序每次运行结束按沙箱裁决给用过的技能 recordSkillEvaluation。skillEffectiveness = (success+1)/(eval+2)（Laplace 平滑，未评测=0.5 中性先验）。loadSkills 一级按有效性、二级按复用次数排序——大脑优先复用真跑通过的技能，而非单纯被复用多次的。

3.6 跨次学习（反思）

这是工厂真正的"长期记忆"。finish/analyze_failure 把 {kind, summary, rootCause, lesson} 写进 FailureReflection 表（按域）。下一次为同域生成时，loadReflections 把最近 8 条注入 system prompt 的"来自之前的反思"块——不靠模型记得，靠这次把教训留下来。路由层还有一道 fail-safe：流结束若没观察到任何 reflect 事件且生成了 agent，就按观察到的 fullChainRan 合成一条，确保下次不健忘。conductor.ts · loadReflections() / finally fail-safe

3.7 人在环路（HITL mailbox）

SSE 是单向的（server→client）。回程是一个 Postgres 表 factory_human_msg：inject 路由 push、conductor 在每个 turn 边界 drainHumanMsgs 取出作为权威 user turn 喂给大脑（是"引导"不是硬命令——大脑可自由分析/重规划）。长工具（sandbox 轮询）也会 hasPendingHumanMsg 中途探，提前 settle 让大脑下一轮就响应。指令也存进 ctx 以 survive 压缩。brain/mailbox.ts · inject/route.ts

v3 相对 v2 的核心范式转变：生成任何代码前先把本体编译成事件图并静态验证闭合，且"代码能判断的事绝不委托给 LLM 判断"。五层独立校验：

5沙箱与真实部署（Inngest 桥）

沙箱不是模拟——它真的把生成的 agent 部署成 Inngest 函数、真的发事件、真的产生可查询的 run 行。lib/agent-factory-v2/deploy.ts · server/inngest/domain-app.ts

5.1 上架 shipAgents

  1. persistSpecs 把 specs 落成 AgentVersion 草稿行（按 versionLabel 幂等）；
  2. 降级该域旧 active 行，把本版翻成 active；
  3. registerDomainApp：upsert DomainInngestApp + PUT callbackUrl 触发 SDK 自注册，让 Inngest introspect；resyncDomainApp 重同步；
  4. 验证真注册：轮询 getDomainApp().sync.functionCount 最多 8×1.2s，functionsRegistered===0 报"部署未生效"（区别于"跑了但没到终态"）。
隔离沙箱部署到专用 app agentic-operator-sandbox-<domain>，与真实域的 app 隔离；事件用 ${domain}/${event} 命名空间前缀，所以 sandbox-raas 永不污染 raas 的运行。会话结束 conductor teardownSandbox 删行 + 重同步（沙箱 app 函数数归零、消失）。

5.2 触发 + 观察 fireAndObserve

  • 算入口事件（被消费但无人产出）→ 发事件（用用户确认的测试用例 payload，或 schema 化的种子）。
  • 静默期 settle：轮询 Postgres 归档表（写穿无滞后），直到 run+事件计数稳定 ≥3 个周期、无 Running、且到达终态。
  • Coverage pass：happy path 只走一条分支——再直接喂每个未跑 agent 的 trigger（最多 3 轮），让每个部署的 agent 至少跑一次，验收门才可满足。
  • 降级检测：从 run output 的 degraded 标记识别"网关挂了走兜底"的假前进——这种链不算跑通。

5.3 生成的 agent 怎么真跑 executeGeneratedAgent

每个生成的 agent 函数被触发时不是 sleep+emit 桩——它真的用自己的 prompt + 案例数据调 LLM、用绑定工具（真 function-calling，最多 6 轮）、并调 decide 工具从候选事件里选恰好一个发出。所以每次 run 都对真实案例推理、选分支。server/inngest/factory/agent-executor.ts

写操作 fail-closed写/双写工具只在 LIVE_WRITE_DOMAINS 白名单的域真做副作用；否则降级 dry-run。沙箱域（isSandboxDomain）+ 测试域恒 dry-run——一个没盘点过的域不会静默发真邀约/写库。

6测试用例验证闭环（带人工确认）

到沙箱阶段，AI 自动派一个"测试用例子大脑"沿事件图造全流程用例，在聊天里展示给用户确认后才真喂进沙箱；跑完展示每个 agent 真实的输入→输出，证明跑通。

  • 自动触发：sandbox_run 首次调用若还没用例，自动 proposeTestCases——不靠 LLM 记得调这个新工具。
  • park 门：conductor 主循环顶部检测 ctx.awaitingApproval → 轮询 mailbox 等 [测试用例决策:执行/重新生成]，turn--; continue 不耗 turn、不烧 LLM；20 分钟超时自动按"执行"（防遗忘挂死）。因为跑在后台，park 能 survive 页面跳转。
  • I/O 采集：settle 后 collectAgentRuns 从 inngestRunArchive（eventPayload=输入、output=输出/emitted）+ agentActivity（决策/工具/reasoning）+ 发出事件的 payload，拼出每个 agent 的 输入事件+payload → 工具 → 输出事件+payload，塞进 sandbox 事件给验证面板。tools/agent-io.ts · collectAgentRuns()

7持久化与耐久性

7.1 进程内后台运行（大脑与请求解耦）

历史上大脑跑在 SSE 请求体内——一断连就 abort 停掉。现在 run-registry.ts 把驱动从请求解耦：一个脱离请求的 driver 跑 runBrain，每个事件推进缓冲 + 通知订阅者 + 节流（3s）落 transcript。brain/run-registry.ts

动作行为
离开页面（组件卸载）关 EventSource = 只取消订阅，后台 run 继续跑
返回页面 / 切回域localStorage 记 ACTIVE_KEY → ?runId= attach → 回放缓冲 + 接实时
SSE 瞬断onerror 自动 reattach（1.5s 后），不会误起新 run
停止任务（按钮）POST /stop → abortRun → conductor 下轮 break → 收尾 aborted（已生成的保留）
run 已结束/被evictattach 读 FactoryBrainRun.transcript 回放 + done
已知局限（已接受）进程内 → dev 服务器重启/HMR 会中断在跑的 run。重连检测到 FactoryBrainRun.status=running 但 registry 没有 → 提示"已中断，点继续"走 convId rehydrate。要抗重启需把 ReAct 主循环迁 Inngest 持久执行（单独立项）。

7.2 会话 checkpoint + 运行存档

  • factory_conversation（裸 SQL 动态表）：内存 LRU Map（40）+ Postgres 镜像。序列化时删 emit/registry/signal（函数），rehydrate 时从 domain+ontology 重建 registry——这让 HMR/重启后"继续"能真续聊而非重来。
  • FactoryBrainRun：整段 transcript(JSON BrainEvent[]) + status/tokens/turns/agentsCount——驱动历史运行列表 + 刷新恢复 + 重开。

7.3 Inngest 归档（监控/验证 survive Inngest 故障）

Inngest dev server 是 run/事件/trace 的实时真相，但易失。两路镜像进 Postgres：

路径机制
写穿中间件在 inngest.send / run start / run finish 时立即写归档表（无滞后、无损）
轮询 archiver独立长驻进程每 30s reconcile（listEvents + listRecentRuns + 终态时拉 step trace），最终一致
读取弹性inngest-source.ts：auto 模式 LIST 读 live∪archive（live 赢冲突）、单 run 读 archive-first + live fallback；MONITOR_READ_SOURCE=postgres 严格只读归档

这也是 §6 逐 agent I/O 能被采集的底座——collectAgentRuns 查的就是这些归档表。

8.1 本体源：live vs snapshot（按用途分裂）

本体来自 Allmeta→Neo4j（live）或 in-repo snapshot。三个入口按用途选不同策略：lib/ontology-generator/ontology-source.ts

8.2 工具注册与按域解析

  • resolveRegistry(domain)：招聘域 → 手写工具库；其它域 → 按本体 tool_use 建声明式 dry-run mock 库。
  • ToolDescriptor.impl{module,export} 是代码生成的关键——AI 写的 .ts 靠它 import 真实模块。
  • suggestToolsForAction 按 action 名 + target_objects 的令牌重叠给工具打分（名中命中 +3、对象命中 +2、描述命中 +1）取 top-N，作为 design 的接地候选。

8.3 SSRF 出站防护

AI 能造 HTTP 工具、能 fetch_doc 抓文档——裸 fetch 能打本机 Postgres(5433) / 云元数据(169.254.169.254)。egress-guard.ts 做 fail-closed 防护：lib/tools/egress-guard.ts

  • isPrivateHost：黑名单 loopback / RFC1918(10/172.16-31/192.168) / link-local+元数据(169.254) / CGNAT(100.64) / IPv6(::1,fe80,fc/fd) / 十进制·十六进制编码绕过。
  • assertPublicUrl：只允许 http(s)；EGRESS_ALLOW_HOSTS 白名单例外。
  • safeFetch：手动跟随重定向，逐跳 re-check（公网→302→localhost 被拦），最多 3 跳。

§已知局限与设计决策

局限进程内后台运行：dev 重启/HMR 会中断在跑的 run（提示"已中断点继续"）。抗重启需迁 Inngest 持久执行。
局限多-Harness 元编排（reuse-vs-generate）尚未接进大脑——design 不自动建议复用既有 agent。
决策无 token 上限（用户拍板）。MAX_TURNS=200 唯一闸，靠自动压缩管上下文，成本只软提示。
决策无渲染兜底——每个 agent 的 .ts 必须 LLM 亲写并过 TS 编译。specToAgentCode 仅留作 dev/测试工具。
决策规则绝不烤进 prompt——rule-check 闸口运行时 ontology.fetchActionRules 动态抓（规则随客户/时间变）。
决策本体读取 fail-closed（strict 不回退 snapshot）；写工具 fail-closed（非白名单域 dry-run）；SSRF fail-closed（黑名单 + 逐跳）。
