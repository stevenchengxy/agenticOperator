01判决 · 你的三连问

能实现、已 LIVE 验证、方向对 —— 但有真缝隙

能不能实现?

能,且不是 PPT。ReAct 循环、三层验收门、指纹防 stale-green、REFINE_BUDGET、mailbox 人介入、sandbox 真部署、跨次反思学习 —— 全部接地真实代码并有测试覆盖。招聘域已 LIVE 跑通:生成 6 agent → 真部署 Inngest → 16 事件链到终态。

该怎么实现?

自由探索 + 确定性出口门的混合,不是显式 FSM。大脑(LLM)自由调工具、跳转、复用已验证部分(迭代价值);但"算不算跑通"从 LLM 手里夺走,交给 finish 里的纯代码三层门。人介入 = turn 边界 mailbox drain。

对不对?

方向对(别上死板 FSM,那会杀掉迭代价值),但有 2 个 blocker。① finish 行为门没用 fullChainRan → 断链也能部署;② v2 有一条 smoke-pass 即自动 ship-to-live 的后门。修完前,"必须沙箱跑通才能部署"只是"打算成立"。

一句话架构判断:把"算不算通过"交给确定性代码而非 LLM 自觉 —— 这是健全的。给大脑自由跳转而非锁死流水线 —— 这保住了"迭代/跳回/复用已验证部分"的核心价值。两者的缝(确定性门)就是安全闸。blocker 全在"门没拧紧",不在"架构错"。

02整体技术架构 · 端到端

从「人说一句话」到「N 个真跑的 Inngest function」

人在 chatbot 说"给招聘域造一套 agent" → SSE 起 runBrain ReAct 循环 → 大脑 read_ontology 从 Neo4j 实时拉本体、把 actor=Agent 动作数当作 agent 数量权威源(招聘=6,不写死)→ 自由 design/codegen/validate/sandbox/inspect/refine → finish 三层确定性门通过才原子持久化为 Fleet draft → Operator 手动 flip 才真上线。

端到端:内部平面(大脑造)→ sandbox 桥接(真跑验证)→ Fleet draft → Operator 人工门 → 业务平面(真上线跑)。

03核心 · 迭代状态机 (你最关心的)

隐式 FSM:大脑就是转移函数 —— 自由跳,但出口门是确定性的

"AI 自行判断从哪一步跳转"怎么实现?答案:没有硬编码的 state→state 状态机。每个 turn 大脑读 BrainCtx 全量结构化状态(buildStateSummary 编进消息当锚点),按"现在观察到什么缺什么"自由调任一工具,工具执行修改 ctx,下个 turn 看到新 ctx 再决定。转移函数 = 大脑本身。但"算不算到终态"不由大脑说了算 —— finish 工具里的纯代码门说了算。

状态 = 工具;转移 = 大脑读 ctx 自由决策(双向、非线性);终态 = finish 确定性门(吸收态)。

AI 自主跳转 · 真实例子(接地代码)

  • validate_graph 返回 agentIssueMap → 大脑不继续 design 剩余的,直接 refine 那一个 → 再 validate
  • sandbox_run reachedTerminal=false → 跳 inspect_run 查哪个 agent 没跑 → refine → 重 sandbox
  • refine 后 score.delta≤−10(回归)→ 主动 revert_refine 回上一好版,换角度
  • finish 被指纹门拒("上次沙箱是改动前版本")→ 被迫跳回 sandbox 重验,不能用旧绿证据

防循环 · 四道闸(已建,接地+测试)

  • MAX_TURNS=200 硬终止 → 保证停机 exists
  • REFINE_BUDGET=3/agent,不可被 re-design 绕过(无 reset 点)→ 封死单 agent FlipFlop exists
  • 指纹失效:改 spec → 旧绿证据作废 → 强制重沙箱 exists
  • 子脑无法递归 spawn(只读工具集)→ 分形深度封在 1 层 exists
诚实缺口(收敛):这四闸防住了单 agent FlipFlop / stale-green / degraded 伪装 / 分形爆炸 —— 真实成果别低估。但不防跨 agent / replan / sandbox 的全局 churn:6 个 agent 各 refine 3 次 + 反复 sandbox 完全可烧到 MAX_TURNS 才被砍断,且 MAX_TOKENS=null。最坏 = 超时,不是收敛。必修:加全局 MAX_SANDBOX_RUNS 预算 + 全局 refine 总数闸(见 §7 / §8)。

04事件流 · 两个平面 + sandbox 桥接

内部「大脑边想边做」流 ↕ 业务「Inngest function 链」,由 sandbox 生命周期桥接
内部平面 = 工厂造的过程(可观测流);业务平面 = agent 跑的过程(Inngest 事件链);sandbox_run 是唯一的桥(真跑出真证据回灌)。
两平面的关键隔离:sandbox-<domain> 与真实 domain app 是两个独立 Inngest app id,fireAndObserve 只轮询 sandbox 前缀的 run。翻到真实 app(业务平面真上线)永不由大脑做 —— 是 Operator 在 Fleet 的手动 flip。

05人介入模型 · 「随时」的真实粒度

人介入 = 一次自然的转移请求(非命令),turn 边界注入

路径:UI 调 inject route → pushHumanMsg(runId,text) 入 mailbox → conductor 每 turn 顶部 drainHumanMsgs 取出 → append 为 {role:'user',content:'[人工介入]...'} + 推进 ctx.humanDirectives(经 buildStateSummary 抗压缩)→ 大脑下一 turn 自由响应("好我改"/"先 inspect 看看再改"/"我已处理")。人不能直改 spec、不能强制 finish —— 原子单位是一个完整 turn。

诚实的局限 ——「随时」被夸大了:drain 只在 turn 边界。纯 LLM-reason turn 是秒级,边界 drain 完全够。但两个长 side-effect 工具是真的洞:
· sandbox_run 阻塞 20~70s —— 你看着它跑偏想喊停,要等整轮 settle 完才被看到。
· spawn_subagent 可达数分钟,且故意不转发 abort signal —— 连断开都停不掉子脑。
修法(P2-1):给这 2 个工具的轮询/turn 边界挂 cancellation 检查点,人发消息即提前返回。不必给所有工具做通用抢占 —— 成本收敛到 2 个工具。
更严重的正确性 bug(P2-3):mailbox 是模块级 in-process Map。多 worker/serverless 下 inject 命中的进程 ≠ 跑 stream 的进程 → 人的介入静默丢失且不报错(MEMORY 里有"僵尸 dev 进程 env 漂移"先例)。修:换 Postgres 表 / pg LISTEN-NOTIFY,drainHumanMsgs 按 runId 查表。

07必修缺口 · 对抗审查揪出的真问题

2 个 BLOCKER + 3 个 MAJOR(全部接地真实代码行)
BLOCKER 1  finish 行为门用 agentsRan===deployed 而非 fullChainRan → 断链也能部署。
sandbox 的 coverage-pass(deploy.ts:269)会直接喂每个未跑 agent 的 trigger 把它单跑,于是一组事件链断裂的 agent(A emit FOO、B listen BAR、没人 emit BAR)照样凑满 agentsRan → 门通过。fullChainRan 值已算好(index.ts:748)却没接进门 —— 这正是你最担心的"绕过验收/链没真串通也能部署"的真实路径,且与设计自称"要求 fullChainRan"直接矛盾。
修(P0-1,S/低):finish 判据(index.ts:1623)加 || !sb.fullChainRan(值现成);verify_chain 断点非空也阻断 finish。
BLOCKER 2  v2 conductor 有一条 smoke-pass 即自动 ship-to-live 的后门(无人工确认)。
conductor.ts:230 if(opts.deployer && smoke.passed) deployer.ship(domain,specs) 用真实 domain(无 sandbox 前缀)→ status:'active' → 真发入口事件。门只有 smoke.passed,没有任何人类确认 —— 与 v3 "sandbox→draft→Operator 手动 flip" 的安全姿态直接矛盾,若真实域 registry 是 live 会触发真外部副作用。
修(P0-2,S/中):加断言 deployDomain 必须 sandbox-* 或域必须 isForceDryRunDomain 否则 throw;或复用已有 bus.emit({t:'needs-human'}) 把 live-ship 卡在人类批准后。
级别问题修法
MAJORcodegen stale-green 天窗 —— codegen 改代码不 null lastSandbox,specsFingerprint 又不含代码内容 → 改代码不改签名时,旧绿证据放行新代码。design/refine/revert 都记得 null,唯独最该的 codegen 漏了。P1-1:codegen 设 generatedCode 后加 ctx.lastSandbox=null;把代码哈希纳入指纹。2 行
MAJOR收敛保证名不副实 —— 全局只有 MAX_TURNS 一根粗闸 + MAX_TOKENS=null,跨 agent/replan/sandbox churn 无界。最坏烧 200 个真 Inngest 部署 turn 后超时,这是超时不是收敛。P1-2:加全局 MAX_SANDBOX_RUNS≈8 + refine 总数闸;finishRefusals 改为"连续 N 次 sandbox 不绿也计数"并在阈值强制只暴露 analyze_failure。
MAJOR写操作 sideEffect 标签纯元数据,不做运行时 gate —— live 模式下 AI 编排的 agent 可无确认真发 inviteCandidate / 写 partner-pg 主表。dryRun 安全靠脆弱的域名匹配 + fail-open 默认(历史上 CJK id 真绕过过)。P1-3:write/dual-write 工具 live 下需 allowlist 或人工确认 token;反转默认为 fail-closed(默认 dryRun,显式 LIVE_ALLOWLIST 才放行)。

09诚实局限 · 别照不存在的东西建

  • 「收敛保证」名不副实:系统会终止(MAX_TURNS 真有效),但全局只有 turn 一根粗闸,最坏是超时不是收敛。加全局预算前别宣传成"高效收敛"。
  • 「必须沙箱跑通才能部署」当前有 2 道合法序列能绕过(BLOCKER 1 + codegen stale-green)。设计意图成立,但代码漏了两刀,修完 P0-1/P1-1 前这条只是"打算成立"。
  • 「人随时介入」被夸大:sandbox/subagent 长工具期间人的消息要干等,且没有"已排队、正卡在沙箱"的即时可见性。
  • 安全姿态强但靠几条未言明的隐式不变量:v3 够不到 live 靠 sandbox 域硬钉 dryRun;写操作不发生靠单个 dryRun 布尔 + 脆弱域名匹配(fail-open)。新域接真 registry、摘 FORCE_DRYRUN、或走 v2 路径,安全会无声塌掉。
  • 可观测性不支撑"看见每个槽进度":UI 卡片硬编码静态 DRAFT 徽章,无 per-slot lifecycle,degraded 没传到 UI。"看得见才能精准介入"目前缺位。
  • ⚠ 这些能力代码里【不存在】,别当已建:ctx.pause/resume · t:human.required · mailbox/conversation 落库 · mid-tool 暂停让人选分支 · AI 自动造工具 impl 代码 + 其安全沙箱。最后这条尤其危险 —— 照它建会引入当前不存在的运行时任意代码执行攻击面。当前 HITL = turn 边界粒度;信任边界 = 人写的 tool registry。
底线结论:你想做的能做、方向对、且核心已 LIVE 跑通。"迭代 + 人介入 + AI 自主跳转"不是空想,是接地代码的现实。把 §7 的 2 个 blocker 堵上(都是小改、值现成),"必须沙箱跑通才能部署"这条命题就真正成立 —— 那时这套自由探索 + 确定性门的混合架构,才是经得起对抗审查的。
