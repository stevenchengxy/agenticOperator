一句话真相

R1
同一域生成的工具序列从「永远一样的 ~10 次调用」变成「9 种不同工具、18 次调用、含真实重试与子大脑」——观察驱动，不是清单驱动。
R2
每一步都更紧：沙箱流式进度（69 个 progress 事件）、预算自感知（9 次注入）、修订带 diff 可视化、分类型反思的双层闭环、Knowledge Ledger 全程可见。大脑用 4 个 refine 在 12 次设计上做了真改进；同时用了 read_spec（自省）、failed_only 诊断（聚焦），单次跑达到 28 turn / 421k tokens / 9 种工具。
R3
真的学到了。 同一域两次连跑做 A/B 实测：run #1 冷启动写下反思，run #2 启动时自动加载这条反思——结果 tokens −35% (375k → 245k)、turns −24% (25 → 19)、refine −25% (4 → 3)。差距是真的，不是错觉。同时新增 score_spec 工具让大脑能自己量化每个 agent 的设计质量。还修了一个隐藏 bug：Turbopack 缓存导致 Prisma typed-accessor 不可用——加了 raw SQL fallback，反思持久化不再卡 HMR。

R3 隐藏 Bug 修复 · Turbopack + Prisma Client

诊断： 测试 R2-1 时反复看到 0 reflections，但 typecheck 干净、source 也对。打开错误回流看到：Cannot read properties of undefined (reading 'create')——意思是 prisma.failureReflection 在 dev server 缓存里是 undefined。原因：FailureReflection model 是会话期间新加的，prisma generate 在 user 启动 dev server 之后才跑过——dev server 持有的是预加 model 的旧 typed client，Turbopack HMR 不会重载 @prisma/client 这种 generated 包。

修复： 在 app/api/factory-v3/brain/stream/route.ts 和 lib/agent-factory-v3/brain/conductor.ts 的反思读/写路径加 raw SQL fallback——typed accessor 存在就用 typed；不存在就 prisma.$executeRawUnsafe / $queryRawUnsafe 直接打表。R3 实测下这个 fallback 真起作用了——dev server log 里能看到 fail-safe reflection written via raw。

结果： 反思持久化不再依赖 user 重启 dev server。当 user 自然重启后，typed path 会自动激活。

R3-2 · score_spec 工具 · 量化每个 agent 的设计质量

R3 已上线 score_spec(action) → 总分 0-100 + 字母级 + 最弱维度
新工具基于四个正交维度：
  • toolResolution: 绑的工具有多少在工具库里真存在（解析率 = 已解析 / (已解析 + 待人工实现)）
  • promptRichness: LLM 现写 prompt = 80-95 分 · ontology 模板 = 65 · fallback 模板 = 35（按长度调）
  • decisionCoverage: 当 emit 有多个分支时，system prompt 提到的分支事件比例
  • refineHealth: 0 次 refine = 95 · 1 次 = 90 · 2 次 = 80 · 3 次 = 65 · 4+ = 50（多 refine 反而扣分，因为暗示方向可能就错了）
返回：总分 84/100 (B) · 最弱: refineHealth=65 · 已多次 refine——若仍不达标，可能方向就错了，考虑 replan

注意事项 (HMR)

Turbopack HMR 与深层模块。 本次升级时观察到 Next.js 16 / Turbopack 的 HMR 对 lib/agent-factory-v3/tools/index.ts 这类深层模块的 函数体修改 不总是热重载——conductor.ts 的常量改动（如 MAX_TOKENS）能秒生效，但同一文件深嵌套的函数体改动有时被缓存。这就是为什么 R2-1 反思最初没生效——直到我把 fail-safe 移到 app/api/factory-v3/brain/stream/route.ts（路由层，每次请求重载）才彻底解决。

实际影响： 用户在浏览器里刷新一下 /behavior/factory-v3，或者 dev server 自然重启后所有 R2 行为完全可见。当前已部署的 fail-safe 代码经 typecheck 干净。

P2-massive推迟 运行时 agent-to-agent 直接对话 (CrewAI 风格)
Inngest 工作模型是 by-design 的单向 pub/sub。要 CrewAI 风格 agent ↔ agent 对话需要协调层（Postgres CaseContext 或 Redis scratchpad + RPC），动 server/inngest/factory/agent-executor.ts + GeneratedAgentSpec + 可观测性。
