Agent 工厂 v3 —— 一个会自己推理的 Harness 大脑

把你回退掉的 v2 重新设计成一个真正「像工程师一样思考」的系统:复用 v2 已验证的确定性脊柱(Conductor + ledger + Bus + SSE),在其上重建一个真·ReAct 认知层,动态生成 tools / agents / skills,在沙箱里对照已有的招聘 agents 反向验证,全部存为草稿,所有内部 AI 的思考实时流到 Claude-Desktop 式右侧活动栏。每个设计选择都标注了它来自哪篇论文或哪个项目。

复用 v2 脊柱 已有、保留 净新认知层 重建 待建/确定性闸门 护栏

本报告由一个 10-agent 研究+综合+对抗评审工作流生成(8 路并行研究 → 1 路架构综合 → 1 路对抗评审,565K tokens),引用 40+ 篇论文/项目。综合稿之外,评审稿揪出了三处对代码库的事实性误判 —— 见 ⑭ 现实校正,这正是「你没想到的」的核心。

①执行摘要

v3 的中心论点(借自 Anthropic / awesome-harness-engineering 的「模型是引擎,Harness 是整辆车」):ReAct 循环只是最简单的 5%,价值在 95% —— 工具、上下文、记忆、沙箱、验证。v2 失败不是因为缺 harness(harness 脊柱是对的),而是认知层在「转录本体」而非「推理」。v3 保留脊柱,把认知层换成真 cognition,具体五招:

  1. 先编译事件图,再写一行代码 —— 从本体直接推导「一节点一 agent、一边一(trigger→事件)」的编排契约并静态校验,杜绝 orphan emit / 不可达终态。
  2. map-reduce 理解本体 —— 永不把 555KB 的能源 actions.json 塞进一个窗口(Chroma 测得 200K 窗口在 ~50K 就开始「context rot」)。
  3. agent-as-code,从固定 operator 库组装 —— 6 个最难的生产模式变成可复用算子,让 LLM 接线而非重新发明(ADAS + AFlow)。
  4. 沙箱内对照真 agents 反向打分 —— SWE-bench 式双清单裁决(正向断言 + 不回归断言),每条规则编译成确定性可执行断言。
  5. Reflexion + Self-Debug 自愈 —— 带 AlphaCodium 测试锚点和硬停止条件,卡住就带完整 ledger 轨迹转人工。

外加一个一等公民的三级记忆系统(工厂 / 技能库 / 运行时,按 CoALA 分类)和四个显式上下文模块(write/select/compress/isolate)。全部跑在你现有的 OpenAI 兼容网关上(chatComplete() function-calling)—— 零 Anthropic API 依赖。每个内部 helper-AI 的思考/输入/输出经现有 SSE Bus 流到右侧活动栏。

②你的需求 vs 我补充的(你没想到的)

你要的(原话还原)

一个有「Harness 大脑」的 AI 工程师,给定目标 + 领域本体,动态合成所需的 tools / agents / skills 并执行/验证 —— 产出与招聘域 6 个手写 agent 同等水准的 agent。运行时要真做 记忆管理 + 上下文管理,每个 agent 的 prompt 按上下文动态拼装(不是静态模板、不是本体规则的转录)。用那 6 个已知良好的 agent 做反向验证,在隔离的「Agents-generation」沙箱里生成+测试,全部存草稿。UI 像 Claude Desktop:左控制台 + 中对话 + 右侧实时展示每个内部 helper-AI 的运行/思考/IO + 最终 agent + 验证分。

我补充的六个高杠杆缺口

记忆做成一等公民的三层系统

你只说了「运行时记忆管理」。把它塌缩成一个向量库会同时破坏三种写/逐出策略。
三个 Postgres 存储,各自独立策略(CoALA):L1 工厂记忆(情景轨迹+语义「策略 X 对域 Y 有效」),L2 技能库(过程性、验证门控、按描述 embedding),L3 运行时记忆(按本体对象 PK 唯一键 → 幂等)。读用 Generative-Agents 打分,写过 mem0 ADD/UPDATE/DELETE/NOOP 合并器。

规则 → 可执行断言(语义验证)

最深的正确性藏在本体 RULES 里,而 LLM-as-judge 会偏爱自己的输出(10-25% self-preference bias)。验收闸门必须是确定性的。
把每条规则(连同 failurePolicy/红线码)编译成对 ledger 事件+步骤结果的确定性 checker,组成 SWE-bench 式双清单。草稿仅当两清单全绿才接受;LLM 评判降级为「带去偏措施的咨询性排序」。

工具适配器合成于类型化 CRUD 层

自由代码生成能碰任何东西(网络/文件/别域数据)—— 致命三连风险。ASI 证明「动作空间里经验证的可执行 skill」比自由文本 skill 包高 ~11%。
生成的工具是薄类型适配器,只能调一个固定的「CRUD-over-本体对象」API;副作用由 harness(非 LLM)经确定性权限/hook 闸授权。LATM 分发器决定复用-vs-新建,CREATOR 的「抽象创建→具体决定」分裂防转录。

先编译事件图(编排是被校验的契约)

你的「6 个 agent」本质是一张事件编排图,不是孤立函数。先生成函数体再校验接线 = orphan emit + 不可达终态。
从 workflow.json 推导「节点-边」图并静态校验(每个 trigger 有生产者、无 orphan emit、终态+HITL 可达)后才生成函数体。每个节点再实现为 Inngest 持久步骤:图=编译期契约,持久步骤=运行时基底。

成本感知拆分 + 代理预测器

多 agent fan-out 耗 ~4-15x token,~80% 质量方差就是 token 花销。把每个草稿都真跑一遍 Inngest+网关是主导成本。
AgentSquare 式 in-context 代理预测器(~0.025% 全评估成本)先给草稿打「大概率通过」分,剪掉弱草稿再付沙箱钱。effort 分级写进 planner;每 agent 运行时 token 预算是一等的、被沙箱验证的约束。

评估/回归 harness + 漂移检测

LLM agent 随机;一次通过的草稿可能间歇失败。而工厂自身质量会随网关模型或本体变化而漂移。
每草稿沙箱跑 5 次,记 mean±variance,稳定 top-k 早停。把反向验证套件冻结成永久回归门;一个定时漂移作业(普通 API route + Postgres 缓存,不上 Inngest)按节奏重跑,质量回退就告警。

③设计原则

  1. Agent = 模型 + Harness。ReAct 循环是简单的 5%;95% 投在工具/上下文/记忆/沙箱/验证。Conductor 始终是一个瘦 while-loop,价值全在它周围的拦截层。
  2. 确定性层 = 护栏/兜底;LLM 推理 = 主力。每个闸门(5 层权限、规则断言、熔断器、infra-vs-business 分类)都是 LLM 无法越过的确定性函数。当作护栏(模型变强可调弱),绝不当主智能。
  3. 原样复用 v2 脊柱,只重建 cognition。保留 in-process Conductor、FactoryBuildRun/Event/LlmCall ledger、事件 Bus、SSE;把被回退的「本体转录」换成真 ReAct/工具调用推理。
  4. 在校准高度生成启发式,绝不转录规则。每个 agent 的 system prompt 是「具体角色 + 强启发式」,从最小高信号上下文拼装 —— 既不空泛也不照搬本体(过度/欠规范两个陷阱)。
  5. 写任何函数体前先编译事件图。接线是从本体推导、编译期静态校验的契约;Inngest 持久步骤是运行时基底(Temporal「图的谬误」)。
  6. 对照真值、确定性地验证。用可执行规则断言 + 反向验证套件(SWE-bench 双清单)做闸门;绝不让 LLM 评判决定接受(self-preference bias)。
  7. 人批准前一切都是 DRAFT。沙箱在技术上无法写生产数据;提升出草稿需 HITL 闸。沙箱边界(能碰什么)与批准策略(何时问人)是正交两轴(Codex 模型)。
  8. 每个 agent 只喂最小高信号上下文。给它 1-hop 切片,绝不给整本体 —— 兄弟 action 是 distractor,会主动劣化生成(Chroma context-rot)。
  9. 记忆是三个设计过的存储,不是一坨。情景/语义/过程性各有写/逐出策略;暴露为 function tool,让循环自己分页记忆。
  10. 让它可读。每个 helper-AI 是隔离上下文的 sub-agent,只回 1-2K token 蒸馏摘要;完整思考/IO 经 SSE 流到右侧活动栏,只有摘要折回 Conductor 上下文。

④分层技术架构

七层。底部 L0 脊柱原样复用 v2;L1 认知核是重建的大脑;L2-L5 是围绕它的护栏/能力层;L6 是 UI。引擎是你现有的 OpenAI 兼容网关。

⑤认知 Agent 循环

Conductor 跑 Codex/Claude-Code 那个经典小循环:while(needs_follow_up){ 收集 call_id 历史; chatComplete()+工具定义; 有 tool_calls → 并行执行+追加+继续; 否则 done }。围着这个小循环的,才是承重的 5 层权限闸(deny 永远赢):

  1. ① PreToolUse / Guardian hook —— infra-failure-vs-business-FAIL 分类(复用 lib/rule-check/infra-failure.ts 的 INFRA_FAIL_REASONS)、recoverable-vs-terminal park 决策都住在这,对所有生成 agent 统一,让它们的函数体保持简单。
  2. ② deny 规则
  3. ③ 沙箱/权限模式 —— 草稿 agent 在技术上无法做生产写。
  4. ④ allow 规则
  5. ⑤ canUseTool(input) → {allow, updatedInput} —— 可重写入参:注入稳定幂等 PK(如 resume-parser 的 md5 etag)、把写操作限定到草稿域、盖 dual-write soft-fail 标记。
现实校正(评审)你以为「网关循环原样复用就行」—— 实际上 server/llm/gateway.ts 在 maxIterations=5 时 throw 且不返回部分轨迹,还有 300s 客户端超时、无流式。所以 Conductor 必须替换这个会抛错的 5 层封顶循环:每轮 checkpoint 到 FactoryBuildEvent、可从最后持久步骤 resume;chatComplete 当「每个 helper-agent 的原语」,不是 Conductor 驱动器。「实时思考流到活动栏」还需要一个目前不存在的流式变体。

⑦端到端生成流水线

  1. 阶段0 · Seed & Plan — Conductor+Planner:读工厂记忆(Generative-Agents top-k)定策略;把已有 agents 作为已评分范例 seed 进 ADAS archive;AutoAgents Planner+Observer 沿事件边界提出 agent 集(对招聘要再推出那几个),critic 剪冗余/补缺;effort 分级。→ FactoryBuildRun + agent 名册 + NOTES/plan
  2. 阶段1 · 理解(map-reduce) — Comprehender×N(隔离):MAP 每个 action → 严格结构化 digest(规则+failurePolicy 逐字保留);分层 REDUCE 成域事件/动作依赖图 + 检索索引。→ digests + graph_ref
  3. 阶段2 · 编译&校验图 — Conductor(确定性):从 digest + workflow.json 建「节点-边」编排契约,静态校验后才生成任何函数体;图坏则快速失败回 Planner。→ 已校验接线契约
  4. 阶段3 · 工具/技能合成 — 复用分发器+ToolSmith:LATM 分发器跑 CRAFT 多视图检索 → 命中则复用,否则 CREATOR 抽象创建(类型化 CRUD 适配器 + OpenAI 工具 schema + 决策规则包 + 自动单测)。→ 工具绑定 + 候选技能包(未提交)
  5. 阶段4 · 生成 agent(agent-as-code) — Generator(每 agent 隔离窗)+PromptWriter:反思 action → 推理其入口事件 → 提 2-3 设计 → 排序 → 以小命名 Inngest 子步骤的 YAML 产出(AlphaCodium,避免 JSON 转义损坏 TS),由 AFlow 算子组合 6 个硬模式。PromptWriter 在校准高度从 1-hop 切片+运行时记忆工作集拼 system prompt(DSPy 从通过轨迹 bootstrap)。Self-Refine 自评门。→ AgentDefinition 草稿 + Agent Card
  6. 阶段5 · 沙箱&反向打分 — 代理预测器→沙箱→双清单评估:surrogate 先剪弱草稿;幸存者部署到每候选重置的隔离域,发入口事件 fixtures(6-8 边界:infra-throw+park、幂等重放、dual-write、business-FAIL、HITL-pending),跑 5 次;确定性评估算 SWE-bench 双清单,对照真值 agents 反向打分。→ 双清单裁决 + pass-rate + variance
  7. 阶段6 · 诊断&修复 — Fixer(Reflexion+Self-Debug):失败时 rubber-duck 解释(agent 行为 vs 要求工作流)→ 断言绑定诊断 → CREATOR 分类工具故障 vs 用法故障 → 在 AlphaCodium 测试锚点保护下只重生成失败子步骤。max_trials=3-4;两次相同诊断早停。→ 修复后草稿 或 升级包(完整 ledger 轨迹)
  8. 阶段7 · 版本&DRAFT — Conductor+skill_add(闸控):两清单全绿 → 提交已验证技能(additive、embedding 键、A-MEM 链)并存草稿(绝不自动激活),把本次语义教训写回工厂记忆。→ DRAFT AgentDefinition + Agent Card;更新技能库+工厂记忆
  9. 阶段8 · 人工审查 — Human(HITL 闸):在右活动栏审草稿(agent 卡、pass-rate 条、推理轨迹);提升出草稿需显式 HUMAN_DECISION(批准策略轴,与沙箱边界正交)。→ 提升决定(或带备注的拒绝,折回工厂记忆)

⑧三级记忆模型

三个 Postgres 存储,按 CoALA 分类命名,全部 Postgres-first、全部暴露为网关 function tool(MemGPT 六操作 + Anthropic 记忆工具命令面的 provider-agnostic 重实现,无 Anthropic API 依赖)。通用读公式(Generative Agents):score = w_recency·exp(-decay·age) + w_importance·importance + w_relevance·cosine;importance 加权衰减是逐出信号,所以「infra-vs-business 分类规则」这种罕见但关键的教训永不被日常杂音逐出。通用写路径(mem0):取 top-10 邻居,一步 function-calling LLM 决定 ADD/UPDATE/DELETE/NOOP —— 这是对抗记忆腐烂的第一护栏。

  • L1 工厂记忆(情景+语义)。情景行就是 FactoryBuildRun/Event/LlmCall 里的构建轨迹;一个定时反思作业(普通 API route + Postgres 缓存,不上 Inngest)对 FactoryLlmCall 跑 LLM 蒸馏出高 importance 语义行(「策略 X 对域 Y 有效/失败,失败模式如下」)。每次构建开头按分 seed Planner —— 这就是你要的「工厂学习闭环」。
  • L2 技能库(过程性、跨域)。skill(name,description,code,tags,embedding(description),status,verified_at,usage_count) + skill_link(A-MEM 式类型链)。按描述的 embedding 索引(非代码,Voyager),CRAFT 多视图检索。仅在沙箱 verify-before-add 门通过后才写;additive-only(无灾难性遗忘)。反向工程那几个真 agent 成命名真值技能 seed:infra-vs-business 分类器 / recoverable-park / dual-write-soft-fail / HITL-gate / fat-payload-choreography / stable-PK。定时 TroVE grow-and-trim 按签名去重(留最通用)、按 usage_count 退役未用技能,保持人可审。
  • L3 运行时记忆(每对象情景+语义)。agent_runtime_memory(... object_type, object_pk ...) 带 UNIQUE(domain,object_type,object_pk,kind),所以同一候选/职位 PK 的重复观察是 UPDATE 而非 append —— 幂等记忆,镜像 agents 的 stable-PK 模式。MemGPT 工作集:小固定切片注入每个 agent 动态生成的 prompt;溢出逐出到 ledger 并在 prompt 头留递归摘要。关键护栏:用 Postgres 行(域,store,key)而非真文件(避免路径穿越);对正确性关键决策,确定性规则断言层始终权威 —— 记忆是优化,不是真值来源。

⑨上下文工程(write / select / compress / isolate)

四个显式、可测的模块,理由是 Chroma 的「context rot」发现:理解能力在远未达窗口上限时就退化(200K 模型约 ~50K),且兄弟内容是 distractor、会主动劣化生成。

  • WRITE = ledger + 每构建 NOTES/plan 工件。所有推理/IO 持久写下,只有引用+紧凑运行摘要进活窗。
  • SELECT(你要的「每 agent 切片」) = 对每个待生成 agent,只检索它拥有的 action + 对 trigger/triggered_event/tool/rules/target_objects 的 1-hop 闭包,把结构化 JSON 对象(非散文)喂进严格 schema function-calling 生成步(NAACL-2024 RAG-for-structured-output,杜绝瞎编事件/工具名)。Lost-in-the-middle 缓解:拥有的 action + 硬约束放开头,输出 schema 放结尾。
  • COMPRESS = (a) 上下文编辑器把 Anthropic clear_tool_uses 旋钮重实现成确定性 pre-call 变换(keep-N≈3、clear_at_least 保前缀缓存、oldest-first、placeholder 占位);清掉的仍在 ledger。(b) Claude-Code 压缩:总结已完成阶段、压缩后重读 NOTES、在 Inngest 持久步骤打点 —— 永不静默删除,总留标记。
  • ISOLATE(你要的「理解 555KB 本体」) = Conductor 为每个 action/workflow 节点起一个隔离 sub-agent —— 沿 JSON 自然单元分块,绝不按字节/token 窗口 —— 各出严格结构化 digest;分层 REDUCE(成对再总结,BooookScore)成域依赖图,永不把 ~140K token 的原始文件塞进一个窗口。
关键不变量digest 里规则/failurePolicy/park 语义必须逐字保留 —— 总结散文,绝不总结控制逻辑 —— 否则压缩恰好丢掉让真 agent 正确的 infra-vs-business/幂等细微差别。

⑩验证与自愈

沙箱 = 隔离的「Agents-generation」Inngest 域,每候选重置(SWE-bench 的 per-task 临时容器;不重置则后一个候选被前一个的残留判定,对幂等-重放断言是致命的)。它在技术上无法写生产 partner-pg/Neo4j —— 生成适配器只能调草稿域类型化 CRUD(沙箱边界轴,与 HITL 批准轴正交)。

反向打分 vs 真值 agents

真 agents 是真值(= SWE-bench Verified)。对每个 action,合成入口事件 payload + 期望发出事件链 + 6-8 边界变体,并先对真 agents 验证每个 fixture(防错误 fixture 误判正确草稿)。裁决双清单(SWE-bench):正向断言(发入口事件 → 要求事件按序出现、跑到完成、规则成立)+ 不回归断言(stable-PK 重放幂等、infra-FAIL throw+park 而 business-FAIL 只写库发事件 —— 复用 INFRA_FAIL_REASONS、HITL waitForEvent 仍挂起)。两清单全绿才接受,跑 5 次记 mean±variance。

规则即断言

每条规则(连同 failurePolicy/红线码)确定性编译成对 ledger 事件+步骤结果的 checker(如「business FAIL 不得 throw」→ 断言 FAIL 分支无 infra-classified throw;「按 stable PK 去重」→ 重放入口事件断言无重复下游 emit)。这些 off-LLM 跑,所以能当闸门。LLM 评判只做带去偏的咨询排序(rubric、位置随机、以真 agents 为锚),绝不当门 —— 否则生成器自己的模型会偏爱自己输出(10-25% self-preference)。

自愈循环 + 停止条件

Reflexion 三角色(Actor=沙箱里草稿 / Evaluator=确定性双清单 / Self-Reflection=Fixer)+ Self-Debug。修复只在 AlphaCodium 测试锚点下重生成失败子步骤(锁住已通过断言,拒绝任何打破锚点的修复,断言按易→难排)。诊断是有界记忆(最近 1-3)。停止:两清单全绿→存草稿;max_trials=3-4 预算停;无进展停(连续 2 次相同失败断言/相同诊断);任何非成功停 → 带完整 ledger 轨迹+累积诊断转人工。

⑪Agent 间通信(两层)

A 层 · 内部 builder crew = supervisor+blackboard 混合。ledger 就是黑板(目标、本体快照、半成品 ToolSpec/PromptDraft/critique、裁决)。每个 helper 读整块黑板,写一个类型化 A2A 式 DataPart 工件(ToolSpec / PromptDraft / CritiqueReport / ValidationVerdict / FixPatch)—— 绝不写自由文本(无类型 handoff 致静默契约漂移),确定性护栏 schema 校验每次写入。Conductor 从黑板内容选下一个 agent。协作动词:前向用 agents-as-tools(调用方保持控制、可追踪到活动栏),仅 Critic→Fixer→Critic 用真 handoff,每步返 Command 式 {update, goto}。确定性熔断器(在 Conductor、非 LLM):硬 max-rounds、每边环计数器(A→B→A 跳闸)、对连续 Critic 裁决做 embedding 去重(抓换词式停滞语义环)、单一 DONE 态(Validator pass)作唯一终止符。黑板持久到 Postgres(非内存 context_variables),所以 Inngest 持久跑和 SSE 栏能扛重启。

B 层 · 生成的运行时 agents = Inngest 上事件驱动编排。编排不是涌现的:它是先编译、静态校验过的事件图,中和了纯 Swarm 的无限 handoff 风险。每节点实现为 Inngest 持久步骤(图=编译期契约,持久步骤=运行时基底),给到精确一次的昂贵 LLM 调用和 resume-from-step。A2A Task 状态机是规范状态词汇,让生成器忠实复现最难模式:input-required(非终态)= HITL waitForEvent;failed(终态)= infra throw+park;completed 带负向 DataPart = business-FAIL 只写库发事件。编译器在编译期注入 stable-PK 幂等契约。每个产出的草稿得一张 A2A 式 Agent Card(skills/triggers/emits/HITL gates),既是注册记录又是活动栏渲染的 schema。

⑫草稿 · 安全权限 · 可观测

草稿与版本

所有生成 agent 存草稿、绝不自动激活,两层强制:(1) 沙箱边界:草稿工具只解析到草稿域类型化 CRUD,技术上无法写生产;(2) 批准策略:提升出草稿需显式 HITL HUMAN_DECISION。版本复用 ledger:每草稿是一个 FactoryBuildRun 关联的 AgentDefinition + A2A Agent Card,带双清单裁决/pass-rate/variance/推理轨迹。代码以 YAML block scalar / 不透明 blob 存(AlphaCodium),让满是引号和模板字符串的 TS 代码在 FactoryLlmCall 里不被 JSON 转义损坏。技能 additive-only 版本化(永不改已有技能,Voyager 无灾难性遗忘)。反向验证套件冻结为永久回归基线;定时漂移作业按节奏重跑、回退就告警。

安全权限

克隆(不导入)Claude Code 的 5 层闸序、deny 永远赢。逐工具独立闸控:每个工具带自己的风险注解,草稿 agent 字面上无法做生产写除非那个工具的闸满足。两正交轴(Codex):沙箱模式设「技术上能碰什么」,批准策略设「Conductor 何时 wait_human」。破坏性注解=强制 HITL。canUseTool 可重写入参注入幂等 PK / 限草稿域 / 盖 soft-fail 标记。一个独立 auto-review reviewer-agent(Codex auto_review)只评估有风险的生成动作,且故意不看生成散文(反 prompt 注入),必须推理工具组合而非单次调用 —— 因为致命三连(私有数据+不可信内容+经 RoboHire/网关外发)是单工具闸抓不到的组合风险。避免批准疲劳:deny-by-default 声明式规则 + auto-review 处理日常,人类 HITL 只留给真正破坏性/终态动作。

可观测

全观测继承自 v2 脊柱,非事后加:每个 LLM 输入/输出已写 FactoryLlmCall,每个类型化跨 agent 工件和断言裁决写 FactoryBuildEvent,由 FactoryBuildRun 范围化 —— 这就是 OpenAI-Agents-SDK 「tracing」的等价物。SSE 把每个 helper-AI 的生命周期(spawn/wait/send/close)和 think/tool/output 实时推到右活动栏;只有蒸馏 1-2K token 摘要折回 Conductor 上下文,但完整流持久且可从 ledger 重放。token/成本计量一等:gateway.ts 已返回 usage{prompt/completion/total}+toolUseIterations+finishReason,所以每构建/每 helper/每草稿的 token 花销被记录展示(多 agent 成本 ~4-15x;~80% 质量方差是 token 花销 —— 必须盯)。

⑬UI 设计(Claude Desktop 三栏)

三栏壳逐字克隆 agent-factory-chatbot.html:.app{grid-template-columns:230px 1fr 440px;height:100vh}。左控制台:品牌头、域选择器(招聘-v1 / 能源调度-v1 / Agents-generation 沙箱)、构建运行列表、生成 agent 草稿注册表(每个带 st-draft 药丸)。中对话:操作员目标 ↔ Conductor 对话,assistant 轮渲染可折叠 details.think(斜体)和 details.tool(mono)块,内联 Mermaid 图(编译的事件图);命中 waitForEvent 闸时内联 .hitl 卡带「批准/提升草稿」。右活动栏(请求的观测核心):tab 切换 —— Agents 面每个 helper-AI 一条 lane(spawn/wait/send/close,状态药丸 st-active/st-valid/st-draft,激活时 .new/.flip 高亮),Trace 面是垂直推理时间线(.ti.tool 青点 / .ti.think 灰点),Eval 面渲染沙箱裁决(.gate 行 + pass-rate 条 + 双清单分解)。所有标签用业务中文,只对代码/产品/技术名词(Inngest/harness/ReAct/HITL/waitForEvent)保留英文。

⑭⚠ 现实校正:对抗评审揪出的盲点

综合稿的文献骨架很强,但对抗评审发现它建在三处对你代码库的事实性误判上 —— 不修正,头号循环一接触现实就断。这正是「你(和我)没想到的」,必须先在 spec 里修,而不是在代码里修。

评审结论有条件通过(作为研究叙事)。文献映射在概念层正确;但从理论到 AO 本体的桥验证不足。在写任何代码前,先修正数据模型假设并与已存在的工厂对账。设计自称的前提(反向打分指标)按现稿对招聘快照并不可构造。

① 招聘本体没有 emit / tool_use 字段

已核验 招聘-v1/actions.json:6 个 action 全是 emit:null、tool_use:null。真正发出事件的字段是 triggered_event[](多值、条件性:如 DD-1 发 DEDUP_PASSED 或 RESUME_LOCKED_CONFLICT)。agents 真正的工具(RoboHire、partner-pg、Neo4j)根本不在本体里。
修正:图编译器对着 triggered_event 写,并加条件模型(每条边带触发该分支的业务谓词 pass/fail/conflict)。工具清单来自手工 registry 映射到 action_steps/side_effects,不是 action.tool_use(它是 null)。明说工具合成 = registry 绑定 + 薄适配器生成,而非本体派生。

② 已存在一个工作中的本体工厂

server/inngest/agent-factory/types.ts + domains/energy/make-agent.ts + feikong 已实现:GateRequest→waitForEvent、branchActions/terminalActions、ComputeResult.emitEvents 条件覆盖、per-action Behavior.compute 契约。而招聘 agents 是手写的、零 waitForEvent。所以「HITL 是招聘 6 个 agent 最难模式之一」是错的 —— 招聘无 HITL;HITL+分支+终态真值在 energy/feikong。dedup 是 2 个 agent(共 7 个文件,不是 6)。
修正:先与已有工厂对账 —— 要么认知层生成 Behavior.compute 函数插进已有 make-agent 工厂(范围小得多、更安全),要么明确论证替换。用 energy/feikong 当 HITL/分支真值、招聘当无-HITL/线性管道真值 —— 两套反向打分套件,不是一套「6-agent」套件。

③ 网关循环会抛错、不可恢复

gateway.ts 在 maxIterations(默认 5)时 throw,不返回累积文本/状态;还有 300s 客户端超时、无流式。深度认知循环(理解 N action→编译→合成→生成→critic→fix)routine 会超 5 轮,溢出则整条在途轨迹丢失。
修正:Conductor 用一个 (a) 抬高/移除迭代上限、(b) 每轮 checkpoint 到 FactoryBuildEvent 可 resume、(c) 把 chatComplete 当 per-helper 原语而非 Conductor 驱动器 的新循环。流式思考到活动栏还需一个目前不存在的流式变体。

④ rules.json 是散文,不是结构化规则

招聘-v1/rules.json 顶层是 project_name/version/description,规则以散文嵌在 description 里,本快照无 per-rule failurePolicy/红线码。结构化规则(带 enforcementLevel)在另一文件/形状。规则 schema 跨域异构。
修正:明说断言对着 7 个 agent 的可观察行为(发出事件+步骤结果+infra-failure.ts 分类)编写,不是从 rules.json 散文自动编译。钉死结构化规则每域真正来自哪(lib/rule-check/rules.json、OntologyRuleCheck、Neo4j);per-domain 规则适配器是净新工作。

⑤ 「技术上无法写生产」是断言,无机制

真 agents 写 partner-pg / Neo4j / MinIO / RoboHire —— 这些是模块级、读 env 的 client,非注入依赖。LLM 生成的 TS 跑在同一 Node 进程的真 Inngest 上,没什么结构性地阻止生成体 import { partnerPg } 或 fetch(robohireUrl)。in-process TS「沙箱」不是安全边界。
修正:指定真隔离:要么 (a) 对生成代码做静态分析/import 白名单,AST 闸拒绝 CRUD-DAL 之外的任何 import;要么 (b) 在独立进程/worker 跑草稿,env 指向一次性 DB + 网络出口拒绝表。诚实标注 in-process 限制(参考 gVisor/Firecracker/E2B;vm2 已不维护)。

⑥ 真值 agents 本身是随机的

7 个 agent 调 chatComplete(解析/匹配/JD 生成)—— 输出随机。SWE-bench 真值是确定性测试,不是另一个随机 agent。把随机草稿对着随机参考打分,只有确定性骨架(哪个事件发)稳,payload 内容不稳。
修正:显式分两个指标:(1) 编排正确性=确定性事件链+infra-vs-business+幂等(真 SWE-bench 形,可打分);(2) 业务正确性=把参考 agent 在钉死模型/seed 下跑一次,录成冻结的(输入→期望输出)golden fixture,对着它打分,而非实时重跑参考。

⑦ 无漂移失效 + 无成本上限

冻结 6-agent 套件做回归基线,但若 AI_MODEL 变(env 是 gemini,易换)或本体/RAAS 契约变,冻结 golden 输出过期,漂移作业会误报/漏报。且「surrogate 剪枝」「token 预算一等」有说,但无硬全局构建成本上限 —— 能源 28 action × N comprehender × 5x × 修复 = 无界 fan-out,无顶层 $ kill switch。
修正:golden oracle 连同(model id、本体快照 hash、RAAS 契约版本)一起版本化;任一变化则失效+重铸,而非告警。Conductor 加确定性 per-build 总 token/成本预算(累加 FactoryLlmCall.usage),越线硬停+转人工 —— per-edge 计数器不约束 28-action fan-out 的总花销。
评审认可的强点harness-vs-loop 论点、把 v2 确定性脊柱当护栏、用确定性双清单(非 LLM judge)当验收门 + LLM-judge 仅咨询并去偏、map-reduce 避 context rot、三级 CoALA 记忆 + mem0 合并器、复用 INFRA_FAIL_REASONS、两正交轴 + 破坏性注解 HITL + 看工具组合的 prose-blind auto-reviewer、一切存草稿 + 确定性熔断器 —— 都正确且有据。

设计自身风险

  • 本体转录复发(= v2 原病):若 Generator 机械映射 action 字段到代码而非真 ReAct 推理,草稿会丢隐含模式。缓解:agent-as-code + CREATOR 抽象/具体分裂 + 验证行为,绝不信一次性转录。
  • 无真值指标 = 无搜索:ADAS/AFlow/DSPy 全靠程序化 pass/fail。若真 agents 的正确行为无法表为确定性断言,整个循环塌成 vibes。建反向验证指标是前提,不是事后。
  • LLM 随机性假阳:一次过的草稿可能间歇失败。必须 5x 记 mean±variance 再存草稿。
  • 成本爆炸:多 agent fan-out ~4-15x token。没有 surrogate 剪枝 + effort 分级,预算被显然坏草稿吃掉。
  • 记忆腐烂:无 mem0 合并器的 append-only 记忆无界增长、用陈旧重复污染检索;纯 recency 逐出丢罕见关键教训。用 importance 加权衰减 + 每次写合并。
  • 技能库污染:沙箱验证前写技能(或收 no-op 技能)会传播坏过程。强制 Voyager/ASI verify-before-add + TroVE trim;additive-only。
  • 混淆两类失败:若 Evaluator 把正确的 business-FAIL(只写库)当沙箱失败,Fixer 会把正确行为「修」成坏的抛错行为。Evaluator 必须像生产 agents 那样分类失败。
  • 压缩丢控制逻辑、无限修复/handoff、致命三连盲点、沙箱状态泄漏、harness 假设随模型变强过期 —— 见各节缓解。

评审追加的高危风险

  • 前提风险(致命):「对照 6 个招聘 agent 反向打分」建在对招聘本体的误读上(emit=null→用 triggered_event;tool_use=null→工具不在本体;招聘无 HITL)。设计自称的前提按现稿不可构造 —— 必须在 spec 修,不是代码。
  • 沙箱逃逸(最高危安全缺口):LLM 生成的 TS 在同进程真 Inngest 上能 import 生产 client。「技术上无法写生产」是断言、无强制 —— 一个幻觉 import 就是真实数据损坏/致命三连路径。
  • 先前技术风险:已有 energy/feikong 工厂解决了 HITL/分支/终态;从零设计而不对账 = 平行分叉、白费 P0-P2。更便宜安全的范围是为已有工厂生成 Behavior.compute。
  • 随机 oracle、成本 fan-out 无熔断、漂移陈旧、过度规范(36 篇引用 vs 4 处破碎的数据模型假设 —— 本身就是「优化了引用完整性而非代码库落地」的信号)。

认知纠偏

✗ 直觉认为

要做这个,得自己造一个像 Claude Code 那样的 code-CLI harness。

✓ 实际上

循环只是 5%,你已经有脊柱。造一个通用 CLI 90% 用不上。偷它的模式(5 层),在你网关上建范围收窄的 agent 生成器。

✗ 直觉认为

本体很完整,工厂把它编译成 agent 就行。

✓ 实际上

「编译本体」就是 v2 失败的转录。本体只是证据;真正的判断(拆分、工具用法、失败处理)要 AI 推理 + 沙箱验证,且招聘本体的 emit/tool_use 字段根本是空的。

✗ 直觉认为

用 LLM 评判生成的 agent 好不好。

✓ 实际上

生成器自己的模型会偏爱自己输出(10-25%)。验收门必须是确定性双清单断言;LLM 只做带去偏的咨询排序。

✗ 直觉认为

「草稿只能调 CRUD 层」就等于沙箱了。

✓ 实际上

LLM 生成的 TS 在同一 Node 进程能 import { partnerPg }。这是约定不是沙箱,直到你用 AST import 白名单或独立进程+一次性 DB 真正约束。

术语表

Harness
围着 LLM 的脚手架(上下文投递、工具接口、记忆、沙箱、验证),决定 agent 成败的承重层。
ReAct
Reason+Act:想→调工具→观察→重复的 agent 循环。
反向打分
用已知良好的真 agents 当真值,把生成草稿对照它们的可观察行为打分。
双清单裁决
SWE-bench 式:正向断言(该发的事件发了)+ 不回归断言(幂等/分类不破)。两者全绿才接受。
context rot
上下文远未达窗口上限时理解力已退化的现象(Chroma);兄弟内容是 distractor。
CoALA
认知架构记忆分类:working + episodic/semantic/procedural。
HITL
Human-in-the-loop;在 Inngest 里用 waitForEvent 挂起等人决定。
infra-vs-business
基础设施故障(throw+park 重试)vs 业务 FAIL(只写库发事件,合法结论)的分类 —— 生产 agent 最承重的不变量。
致命三连
私有数据 + 不可信内容 + 外发能力同时具备时的组合风险。
DRAFT
生成 agent 的默认状态:技术上无法写生产,提升需 HITL 批准。
